# Slovak speech-to-text test demo

Internal tool for comparing speech-to-text models for Slovak: on-device (offline) models and cloud (online) models behind one interface, with accuracy and performance metrics. It is a test tool, but the pipeline mirrors the planned production one:

```
Microphone → Silero VAD → Router → [ Online cloud STT | Offline on-device STT ] → shared normalization (scoring) → transcript
```

Language is forced to Slovak (`sk`) everywhere a model lets us set it.

## Quick start

### 1. Proxy (holds the API keys)

Needs Node 22 or newer. No `npm install`.

```bash
cd proxy
cp .env.example .env      # then put your keys in .env (git-ignored)
node server.js
```

- Engines without a key are listed in the app as "no key on proxy".
- Set `PROXY_TOKEN` in `.env` whenever the proxy is reachable from more than your own machine, and enter the same value in the app's Settings. Without it anyone who can reach the port can spend your provider credits.
- `ENABLE_MOCK=1` adds a `mock` engine that needs no key: useful for trying the app end to end.
- Data-processing region is chosen per provider with the `*_BASE_URL` variables (see `.env.example` and the [provider table](#online-engines)).
- The proxy also serves `models_out/` at `/models/…` so phones can download the models you converted.
- Tests: `node --test` in `proxy/`.

### 2. App

Needs Flutter 3.44+ (stable is 3.50 / Dart 3.14 as of 2026-11-12), JDK 17, Android SDK 36; Xcode for iOS.

```bash
cd app
flutter pub get
flutter analyze
flutter test
flutter run
```

Then in the app:

1. **Settings** → set the proxy URL (`http://10.0.2.2:8787` on the Android emulator, `http://<your computer's LAN IP>:8787` on a phone) and token → *Save & test connection*. This also loads the list of online engines.
2. **Models** → download an offline model. Models are never bundled in the app.
3. **Record** → pick a mode and engines, record.

`android/` and `ios/` are already in the repository. `python tool/setup_platforms.py <org>` is only needed to regenerate them from scratch.

### 3. Offline models

Two kinds (column "Hosting" in the [model table](#offline-models)):

- **Direct**: downloaded by the app straight from Hugging Face (stock Whisper small, stock Parakeet, third-party KInIT Parakeet export). Nothing to prepare.
- **Self-converted**: the Slovak Whisper fine-tunes exist only as PyTorch weights, so they must be converted once on a computer. The result lands in `models_out/<id>/`; the proxy serves that folder; the app's Model Manager downloads from the proxy (or any static host you set as *Model host URL*).

```bash
python -m venv .venv && .venv/Scripts/activate          # Linux/macOS: source .venv/bin/activate
pip install -r tools/convert/requirements-whisper.txt
python tools/convert/convert_whisper.py kinit-whisper-small-sk     # one model
python tools/convert/convert_whisper.py --all                      # all Whisper fine-tunes in the catalog
```

Parakeet (KInIT Slovak fine-tune, NeMo checkpoint; Linux or WSL2 only):

```bash
pip install -r tools/convert/requirements-parakeet.txt
python tools/convert/convert_parakeet.py
```

What the scripts do, exactly:

- `convert_whisper.py`: downloads the pinned Hugging Face revision, renames the weights into an `openai-whisper` model (strict load, then checks the logits match the Hugging Face model), runs the **unmodified** sherpa-onnx exporter `scripts/whisper/export-onnx.py` at commit `29b735c` on it (opset 17), and keeps the int8 files. Quantization: onnxruntime `quantize_dynamic`, `op_types_to_quantize=["MatMul"]`, `QInt8`.
- `convert_parakeet.py`: downloads the `.nemo` checkpoint and runs the unmodified sherpa-onnx `scripts/nemo/parakeet-tdt-0.6b-v3/export_onnx.py` at the same commit. Quantization: `quantize_dynamic`, `QUInt8` encoder, `QInt8` decoder and joiner.
- Both write `manifest.json` (file sizes, SHA-256, source revision, quantization). The app verifies downloads against it and records the quantization string with every result, so what is measured is what would ship.

### 4. Test sets

A test set is a folder of `clip.wav` (16 kHz mono) + `clip.txt` (reference; empty file = no-speech clip), plus an optional `terms.txt` (key terms, one per line).

```bash
python tools/datasets/download_testsets.py fleurs --limit 100 --zip          # Google FLEURS sk_sk test, CC-BY-4.0
python tools/datasets/download_testsets.py nospeech --count 20 --zip         # synthetic silence/noise, empty references
python tools/datasets/download_testsets.py commonvoice --archive <cv-sk.tar.gz> --limit 100 --zip
```

Common Voice is no longer on Hugging Face. Since October 2025 it is only distributed by [Mozilla Data Collective](https://mozilladatacollective.com/datasets/cmu62gcol00ohnq0758656ndx) (Slovak 27.0, CC0), which needs an account, an API key and acceptance of the dataset terms (no re-hosting, no speaker re-identification). Download the archive there (or with `pip install datacollective`), then run the `commonvoice` subcommand on it.

Get a set onto the phone with the Benchmark screen's *Import zip* button, or `adb push testsets/fleurs-sk-test /sdcard/Android/data/<app id>/files/testsets/`.

## How it works

### The engine interface

Every model sits behind [`SttEngine`](app/lib/core/stt_engine.dart):

```dart
abstract class SttEngine {
  String get id;  String get displayName;  bool get isOnline;  String get quantization;
  Future<void> load();                                   // init model / check API
  Future<SttResult> transcribe(AudioClip clip);          // batch
  Stream<SttPartial>? transcribeStream(Stream<Float32List> audio) => null;   // optional
  Future<void> dispose();
}
```

`SttResult` carries text, processing time, model load time (when a cold load happened), network latency (online) and provider metadata.

### Modes

| Mode | Behaviour |
|---|---|
| Online only | VAD-trimmed audio goes to the selected cloud engine through the proxy. |
| Offline only | Chunks are transcribed on the device while you are still recording. |
| Auto | On stop, the proxy is probed; if it answers within the timeout (default 3 s) the online engine is used, otherwise offline. A retryable online failure also falls back to offline. The route taken is stored with the result. |
| Draft + upgrade | Offline draft immediately (editable, labelled DRAFT). The saved audio is then sent to the online engine; its transcript replaces the draft. If you edited the draft meanwhile, the app asks which text to keep. Pending upgrades are retried every 30 s and from the History screen. The audio file is deleted once the online transcript has succeeded (unless "Keep audio after upgrade" is on). |
| Simulate offline (toggle) | Forces the offline path in every mode; upgrades wait. |

### VAD and chunking

Silero VAD (through sherpa-onnx) runs in front of both paths. Settings: speech threshold (0.5), end-of-speech silence (0.7 s), padding before/after (0.2 s), minimum speech, longest chunk (25 s). Each time VAD closes a segment, the padded audio becomes a chunk; in offline and draft modes it is transcribed immediately on a background isolate, so the draft is complete moments after you stop. Whisper in sherpa-onnx discards audio past 30 s per call, which is why chunks are capped at 25 s (and raw clips are windowed at 28 s when VAD is off).

**Whisper and VAD chunks.** sherpa-onnx lets Whisper emit at most 6 tokens per second of the audio it is given (`num_feature_frames / 100 * 6` in its greedy decoder; the `tail_paddings` option does not raise it). A VAD chunk is dense speech with the pauses trimmed off, and Slovak needs more tokens than that, so the transcript was cut off mid-word. The app and `evaluate.py` therefore append silence to every piece given to Whisper, equal to half its length and never beyond the 28 s window (`kWhisperSilencePad` in `offline_worker.dart`, `WHISPER_SILENCE_PAD` in `evaluate.py`). Pieces longer than about 19 s cannot get the full amount. Parakeet has no such limit and is passed unchanged. Measurements are in the [verification log](#verification-log).

### Metrics

Captured for every transcription and exportable as CSV and JSON (History → share icon): engine id and name, quantization, device model, OS version, audio duration, speech duration (after VAD), processing time, real-time factor (processing ÷ speech duration), time from stop to text, model load time, peak memory, network overhead and provider time (online), route taken, transcript, provider metadata.

Peak memory is best effort: the app samples the process's resident set size every 150 ms while the engine runs. It is the whole app process (Dart + native model memory), not the model alone.

### Benchmark and scoring

The Benchmark screen runs any selection of engines over a test set and reports WER, CER, hallucination rate (share of no-speech clips that produced any text), key-term accuracy, RTF, average latency, peak memory and load time, plus the WER of each offline engine measured against each online engine's transcript. Per-clip rows show a word-level diff. Export: summary CSV, per-clip CSV, full JSON.

"Run clips through VAD" on = the production pipeline (a silent clip never reaches the model). Off = the raw clip goes to the model, which shows the model's own tendency to hallucinate.

**Normalization** is applied before scoring, identically for every engine and in both languages: lowercase; compose combining marks; join thousands groups; replace everything that is not a letter or number with a space; spell out digits in Slovak (`21` → `dvadsať jeden`); split compound numerals into the same pieces (`dvadsaťjeden` → `dvadsať jeden`); unify numeral variants (`dve` → `dva`); collapse whitespace. Slovak diacritics are kept. The rule data lives once in [`shared/normalization/sk_rules.json`](shared/normalization/sk_rules.json); the Python module reads it directly and the Dart constants are generated from it (`python tools/common/gen_dart_rules.py`). Both implementations run the same [`test_vectors.json`](shared/normalization/test_vectors.json).

Not normalized: ordinals (`1.` vs `prvý`), decimals, dates, times, declined numerals (`dvoch`). Mapping `jedna/jedno → jeden` and `dve → dva` is applied to all text on both sides, which costs a little sensitivity on those words but is the same for every engine.

## How to add a new engine

- **Another offline model on sherpa-onnx**: add an entry to [`app/assets/models.json`](app/assets/models.json) (`family`: `whisper` or `nemo_transducer`; `hosting: url` with file URLs and hashes, or `hosting: self` plus a conversion script that writes `models_out/<id>/manifest.json`). It then appears in the Model Manager, the pickers, the benchmark, the attributions screen and `evaluate.py`. No Dart changes.
- **Another model family on sherpa-onnx** (e.g. SenseVoice): add a `case` in `_config()` in [`offline_worker.dart`](app/lib/engines/offline_worker.dart) and in `OfflineEngine` in `evaluate.py`.
- **Another cloud model**: add an entry and an adapter function in [`proxy/engines.js`](proxy/engines.js) (get audio bytes, return `{ text, meta }`), plus a test in `server.test.js`. No app changes: the app reads the list from the proxy.
- **A different runtime** (whisper.cpp, WhisperKit, …): implement `SttEngine` and add an instance in [`engine_registry.dart`](app/lib/engines/engine_registry.dart).

## Known gaps and blockers

Not done, with the reason:

1. **The Flutter app has never been run on a device.** It analyzes cleanly, its unit tests pass and the Android debug APK builds, but nothing was exercised at runtime (microphone, VAD, sherpa-onnx inference in the background isolate, model downloads, draft → upgrade, the screens). Expect runtime fixes on first launch. iOS is not built at all (needs a Mac and Xcode).
2. **Realtime/streaming is not implemented** for any engine. `SttEngine.transcribeStream` exists and returns null. Batch covers all four modes. Doing it properly needs a WebSocket relay in the proxy (keys must stay server-side) and partial-result UI. Endpoints are in the table above.
3. **No provider was called for real.** The proxy adapters follow the documented shapes and are tested against fakes. Three shapes could not be confirmed from the docs and are flagged in the app's engine list: the multipart spelling of `languages[]` for `gpt-transcribe`; the inline-audio request for `gemini-3.5-transcribe`; Slovak on Scribe v3.
4. **Opus compression before upload is not implemented** (it was optional). Audio is uploaded as 16 kHz mono WAV, about 1.9 MB per minute.
5. **Language cannot be forced on Parakeet TDT v3.** The NeMo transducer has no language input; the stock multilingual model picks the language itself. The KInIT fine-tune is Slovak-only, so this affects only the stock baseline.
6. **Parakeet conversion was not run** (NeMo needs Linux; the authoring machine is Windows). The script is provided. A third-party export of the same KInIT checkpoint is in the catalog so the model can be tested right away; it is from an unaffiliated account and was not audited.
7. **Summaries** (the stretch "compare LLM summaries" button) need `SUMMARY_PROVIDER` and `SUMMARY_MODEL` set on the proxy. No default model is set, on purpose: chat-model IDs were not part of the verification.
8. **Benchmark audio must be 16 kHz WAV**; the dataset script produces that. VAD for benchmark clips runs on the UI isolate (fine for clips of a few seconds, would stutter on very long files).
9. **Whisper medium** runs at about real-time speed on a laptop CPU (RTF 0.9 to 1.1) and its benchmark process peaked at 3.7 GB, so expect it to be slower than real time on a phone and at risk of being killed by the OS.
10. **Cleartext HTTP** is enabled in the generated Android/iOS projects so the app can reach the dev proxy on your LAN. Put the proxy behind HTTPS and remove that exception before any wider distribution.

How to read it:

- **The Whisper "VAD on" column predates the silence-padding fix and is too high.** With VAD on, Whisper deleted about four times as many words (KInIT small: 1,166 deletions against 299 with VAD off, of 15,486 reference words) because of the 6-tokens-per-second limit described under [VAD and chunking](#vad-and-chunking). The fix was measured on a 66-clip sample of the same set for `kinit-whisper-small-sk`: 12.0 % WER without padding, 7.3 % with 50 % silence appended (7.9 % with 100 %, 7.0 % with 200 %; 7.7 % with VAD off), at about 15 % more processing time. The full set has **not** been re-run with the fix, for any model.
- **Hallucination** is the share of the 10 no-speech clips (silence, white and brown noise, hum, clicks) that produced any text at all, even one letter. With VAD on, the model is never called for these clips.
- **Possible train/test overlap:** the KInIT Parakeet card lists FLEURS among its training data without naming the split, so its number here may be optimistic. KInIT's own figures are 7.9 % on Common Voice 24 and 6.6 % on their internal set.
- FLEURS is clean read speech. Speed is for this laptop's CPU, not a phone. The process peak memory in the result files is for the whole Python benchmark process, not the model.

- Flutter 3.50.0: `flutter analyze` (0 errors, 0 warnings; 9 deprecation notes because Flutter now wants `package:material_ui` instead of `package:flutter/material.dart`), `flutter test` (46 of 46 after the Whisper padding tests were added), `flutter build apk --debug` (success, 240 MB debug APK with all ABIs).
